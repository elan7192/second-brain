# How it works

This vault is a compiler. See [[llm-wiki]]. Obsidian is the IDE. See [[Home]] and [[graph]]. Operating order: [[musk-algorithm]].

## Loop

1. lan E drops a source in `raw/` or pastes a URL and says ingest.
2. Agent ingests. One source updates the pages it actually changes. Lint. No ingest brief unless asked.
3. lan E asks. Agent reads [[index]], then only the pages that question needs.
4. File the answer to `wiki/` or `output/` only if the next session would re-derive it.

GrowthOS notes live in `growth/`. Load [[growth-core]]. Do not mix DEMO partner figures into [[MEMORY]]. See [[growth-operator]]. Scout inbox is paused. See [[assign-execute-verify]].

## What the model sees

Prefer compiled pages over raw dumps. That is [[tokens-as-capital]] and [[context-graph]].
The short [[index]] is the door. [[index-papers]] and [[index-sources]] are opt-in catalogs (D9).

[[MEMORY]] stays small. That is [[memory-ablation]].

Schema rules stay checkable. That is [[verifiable-instructions]].
