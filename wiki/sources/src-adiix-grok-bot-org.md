## Claims kept

Chief routes; does not do the work. Triage → delegate → watch → collect → escalate. A Chief that researches/writes/operates itself rebuilds one giant chatbot.

Hire by bottleneck, not by app icon. Split the organization where work gets blocked. Add a Bot only when a recurring bottleneck has a distinct outcome, source set, style, or approval boundary.

Every Bot needs a contract: responsibility + sources + judgment criteria + reporting format + forbidden actions. Personality prompts are not enough.

Grow the company from mistakes. Turn a repeatable failure into a permanent rule in the narrowest place (contract, Skill, source policy, approval, handoff, Routine). Same correction three times manually is unpaid QA.

All Bots share one persistent cloud computer (own screen each). Separate Bot ≠ separate security boundary. Audit what exists on the shared machine; prefer minimum access and scoped identities.

`/workspace` is the internal bus. Hand off artifacts (files), not giant chat messages. Handoff packet: task, status, output, sources, decisions, uncertainties, next owner, do-not-assume.

Three gates on every serious automation: source → evidence → action. A Routine must not bypass a gate.

Humans approve only money, publishing, deletion, signatures, and irreversible external actions. Bots may research, draft, summarize, reconcile, verify, and queue.

Bans / expensive lessons: constant polling burns quota; syncing everything wastes usage; bad retries duplicate actions; undocumented internals break; too many Bots can slow the system. Prefer event triggers over polling; quiet success (notify on exception).

Skills are earned: real task → correction → Skill → test → Routine. Memory stores preferences/rules, not changing reality (prices, balances, live status). Reopen authoritative sources for consequential facts.

House filter: CoS remains front door. No Jenny hire. No auto-merge. No 5/15-min polls. No new rooms. Prefer fold over new bots. Product LanBB; semantica tool.
